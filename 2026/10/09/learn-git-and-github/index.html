notes about git & github

git

概述

文件的三种状态：

  • 工作区（working directory）：就是眼睛看到的现在文件的样子，存储在磁盘上的文件样子
  • 暂存区（staging area）：过渡态，git add 之后准备提交的文件的样子
  • 版本库（repository）：git commit 之后的文件样子

常用命令

操作类

  • git init：当前目录创建为 git 仓库

  • git add：添加进暂存区（工作区复制一份到暂存区）

  • git commit -m "{message}"：提交改动，写入版本库

  • git reset --[hard / mixed / soft] 版本号：版本回退

    版本号介绍

    • 第一种表示

      HEAD 为当前最新提交，HEAD^ 表示最新的前一次，以此类推 HEAD^^…

      也可以用 HEAD~n 表示往前的第 n 个版本

    • 第二种表示

      具体的一大串版本号，可通过 git log 查看，写的时候取前5位就可以

    三种模式的区分（例子：git reset --[ ] HEAD^）

    模式 版本库 暂存区 工作区
    hard 回退至上一版本，设为 Z Z Z
    mixed 回退至上一版本，设为 Z Z 不变
    soft 回退至上一版本，设为 Z 不变 不变

  • git restore

    • git restore <file>：撤销工作区的改动，用暂存区的内容，覆盖工作区
    • git restore --staged <file>：把文件从暂存区退回 HEAD 的版本

    例子（上面2个命令连着使用）：

    提交完之后 (工作区, 暂存区, 版本库) = (A, A, A)，不小心改动了工作区（C），同时还 add。此时是 (C, C, A)

    回到了 (A, A, A)

  • git rm <file>：删除工作区的 file，同时同步到暂存区

    之后再用 git commit 就可以提交删除后的新状态

查看类

  • git status

    • 比较暂存区和版本库：有差异则显示 Changes to be committed
    • 比较暂存区和工作区：有差异则显示 Changes not staged for commit

  • git diff：查看工作区和暂存区的不同

  • git log：查看每一次的 commit 记录，按最近到最久远排列，获取每一次 commit 的 commit_id

  • git reflog：相比于 git log 多记录了一些其他的操作，比如 resett，“找到每一次 commit_id”比 git log 更好

分支管理类

  • git branch <分支名>：创建分支
  • git switch (-c) <分支名>
    • 不加 -c，则切换分支
    • 加 -c，则创建分支并切换到它
  • git branch：查看分支，当前分支会标明 *
  • git merge <分支名>：合并分支到当前分支
  • git branch -d <分支名>：删除分支

一些理解

分支管理

  • 实际上每一条分支就用一个指针代表，不同的分支共享一个有向无环图，图中的每一个节点都是一个 commit
  • 而 HEAD 是指向当前分支的指针，即指针的指针，它能定位我们现在处于哪条分支上
  • 主分支是 main / master
  • 建立分支：实际上就是建立一个指针，指向当前分支的最新提交

分支如何合并？

例如，现在的主分支 main 上，HEAD 指向最新的提交（readme.txt），执行命令 git switch -c dev

变化如下：

  • 当前分支是 main，因此 dev 分支创建的时候它指向了 main 的最新提交位置，即和 main 指向了同一个位置
  • 同时 HEAD 指针发生改变，指向了 dev（因为 dev 现在变成了当前分支）

如果此时我往 readme.txt 中加了底部一行内容，并 add & commit，那么此时新的提交（节点）产生，dev 会指向它，而 main 不动

接下来我们把分支切换会 main，会发现工作区的 readme.txt 的新添的那一行不见了

这是因为每次分支切换，都会用目标分支最新提交的内容，去更新工作区和暂存区 。由于 main 的最新提交并没有那一行（我们改的是 dev 分支），所以工作区不会显示

接下来我们可以在主分支把 dev 合并进来，并删去 dev 分支
